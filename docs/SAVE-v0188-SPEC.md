# 0.18.8 航程使用權與多分頁保護

基準：`5a45359695b5825ba7cf7e9271dc88901f647a49`（已發布 0.18.7）。延續工作單 `docs/parity/issues/01-save-and-lifecycle.md`，不將本切片等同整項商用或 Wii 對等驗收完成。

## 玩家可觀察的要求

1. 同一瀏覽器來源的一份航程一次只在一個遊戲分頁使用。兩個分頁同時啟動也不能各自保存舊進度；所有權由瀏覽器 Web Locks 排他機制取得，不能靠時間租約或 localStorage 的先讀再寫冒充互斥。
2. 第二分頁在讀取航程、搬移舊照片或建立 3D renderer 前停止，顯示可讀且鍵盤／觸控可用的提示。關閉原分頁後可重新嘗試，重新讀取最新資料；不得沿用舊記憶體搶占。
3. 航程、日誌／設定、照片寫入、匯入及失敗還原均受使用權保護。停止使用的分頁不得在延遲回呼、隱藏、關閉或返回快取時再寫入。
4. 匯出只產生此分頁的一致備份，不得順便保存或採用別頁的照片索引。保留待救援照片；無法完整匯出時明確失敗，不產生假的完整備份。
5. 一般切換分頁不強迫重載。離開頁面或瀏覽器凍結後停止新操作；待進行中的照片／匯入完成才釋放使用權。返回已終止的分頁必須重新讀取，不重新啟用舊進度。文件被銷毀時使用權由瀏覽器釋放。
6. 不支援或拒絕 Web Locks 時顯示相容性與重試提示，不偷偷略過保護或聲稱已有暫存遊玩模式。
7. 舊版本分頁不遵守新鎖定機制；以 storage 事件及寫入前快照比對偵測外部航程變更，停止本頁保存並保留可匯出的記憶體進度。明確要求關閉舊版本分頁；不能聲稱能阻止舊程式已發生的寫入。
8. 自由探索、指標／觸控生物選取、自動畫質、既有圖鑑及相簿保留。背景頁與第二分頁不額外啟動 GPU 工作。

## 驗證界面

沿用整體規格既有的實際瀏覽器操作、正式存讀檔函式及瀏覽器儲存 API 故障注入界面。測試排他取得、延遲取得後終止、不支援／拒絕、舊分頁外部修改、照片／匯入延遲、唯讀匯出、關閉後新分頁續玩及桌機／觸控介面。主流程以實際 Chrome 雙分頁為證；觸控模擬不當作實體手機驗收。

未包含本切片：跨 localStorage 與 IndexedDB 的程序崩潰原子匯入、日誌備份遷移、跨裝置雲存檔、完整真人及長時間實體裝置驗收。這些仍依原工作單追蹤。

設計依據： [Web Locks 規格](https://www.w3.org/TR/web-locks/)、[頁面生命週期](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)；2026-10-26 查閱。瀏覽器鎖只協調遵守同一機制的程式，不取代實際存檔錯誤處理。
