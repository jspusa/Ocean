# 0.18.28 — 透明生物的攝影散焦

固定基準 `f38a5ef5a1398bd132cb350701a7be88df440c47`（已發布 0.18.27），依 [本輪規格](parity/TRANSPARENT-PHOTO-v01828-SPEC.md)。本輪修正桶眼魚透明頭罩在大光圈、焦點落在生物後方時出現多條分離輪廓的問題。完整擬真、Wii 功能對等、實體手機、耗電、公網多人及商用驗收仍未完成。

## 實作範圍

原路徑以九次偏移幾何逐次透明混合，散焦輪廓因而分離。新路徑先將同一個體的透明表面寫成一張帶自身深度的局部影像，再以有界連續濾波合成；維持原本光照、水中衰減及遮擋。清楚對焦保留原 shader 和單次直接繪製，原個體 UID、0.14 m 尺度、690 m 棲地、模型、自然動作與自動畫質均保留。

重用已被後製消耗的兩張 volume 貼圖，不新增貼圖或全畫面 pass。局部 tile 具有 halo，清除與繪製均限於有效區域。相同 actor 的高低 LOD 先寫同一影像才濾波；不同 actor 即使 UID／位置相同仍分開排序合成。水族館 spread clone 依各自 packed buffer 保存 actor 對應，防止改寫來源批次。

新增兩個初始化 shader program，沒有宣稱啟動成本完全不變。全部頭罩在相機後方時不提交散焦；極小 scratch 依實際尺寸縮小支援範圍並重新正規化權重。這是非折射、顯示色彩空間的局部透明近似，不是完整物理光學或實體生物材質校準。

## RED、負控制與影像

先固定當前正式版本的桌機及觸控原生 GPU 影像，保留原始 PNG、report 與來源雜湊。以歷史 focused 頭罩在十個固定輪廓位置的訊號，建立獨立連續 disk 參考；固定門檻在讀取候選影像前完成。這是 display-code signal／輪廓形狀測試，不能稱物理能量或整體畫質分數。

正式測試另要求每條輪廓保留訊號、RMS 寬度及 normalized profile L1。銳利單層、全局淡化及只淡化一條輪廓都被負控制拒絕；不能靠隱去透明罩取得 GREEN。focused on/off 與 far-off 完整 RGBA 必須與釘住的原版相同。

首次觸控修復在 focused 畫面有一個像素相差一級，測試確實拒絕。之後保留原 focused shader 逐字相同，將局部影像輸出分成獨立 program，才取得完整相同結果；沒有放寬逐像素門檻。原始診斷、失敗候選與 81 樣本探針都保留於 `qa/parity/v01828-shell-dof/`。

## 狀態與所有權

Renderer → WebGL 記錄測試執行正式 batch／packing／提交方法。先以保留的舊來源重播 RED，再以同一測試取得 GREEN。覆蓋局部 scissor clear、既有 scissor 交集與例外還原、MRT 附件拆除、全背向拒絕、微小目標有界取樣、同 actor LOD 合併，以及同 UID 不同物體與水族館 clone 的獨立所有權。它不執行 shader 像素，不代替原生遮擋與效能測試。

## 正常玩家流程

桌機與觸控各 31／31：新航程正常入海，沿實際導覽至 690 m，主動指向同一個體、觀察、暫停、清除名稱、以正式相機滑桿設定 f/2 與 3.6 m 對焦、真正快門、繼續至中層站、回首頁沖印及重載。相機範圍控制以原生鍵盤 range 操作；觸控的游泳、指向與按鈕使用單一 CDP 觸控串流，屬電腦上的觸控模擬。

同一張原 JPEG 在預覽、沖印、重載後 bytes／SHA-256 保持一致。正常 render callback 的九個區域抽樣沒有黑幀或非法 GL，未主動選取時沒有魚名卡片；抽樣不是所有 framebuffer 像素或全部裝置的保證，也不能拿受 readback 影響的幀間隔當 FPS。
