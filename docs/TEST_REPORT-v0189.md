# 0.18.9 匯入中斷恢復與日誌備份

基準 `1e16816b33b4c2947139133be5a1345d361cbf7e`（已發布 0.18.8）。本輪依 [規格](SAVE-v0189-SPEC.md) 補上跨 localStorage／IndexedDB 匯入的中斷恢復及日誌備份，經 AskMatt TDD、獨立 Standards 與 Spec 審查。這份報告記錄本機證據；線上發布仍待補證，整體商用與完整功能對等尚未完成。

## 實作與玩家行為

匯入時，以同一個 IndexedDB 交易保存舊照片原圖、相簿索引及四份 localStorage 原始快照，再替換照片。新的航程、日誌及其備份完成保存後，才刪除恢復紀錄；該刪除交易完成才算匯入提交。交易要求嚴格持久性；本輪的實際驗證範圍是 Chrome renderer 程序崩潰，不將它宣稱為裝置斷電或底層硬體故障保證。

下次啟動先取得既有分頁使用權，處理尚未完成的匯入，之後才讀取日誌、建立 Renderer 或執行功能搬移。恢復先寫回 localStorage，再以一個資料庫交易還原照片並刪除恢復紀錄；恢復途中再度中斷，可以重新嘗試。現值必須符合原始值或本次預計的新值，未知外部修改不自動覆寫。離頁等待包含啟動恢復與完整匯入，不在其仍可寫入時轉移使用權。

若啟動恢復失敗，停止載入並顯示重新讀取與備份入口。此時備份讀取持久恢復紀錄，保留原航程、投稿引用和原圖，不以未載入的預設航程代替。已有的記憶體救援及唯讀匯出仍可用；匯入備份攜帶的待救援照片也會保存，重開後可重試或明確放棄。匯入進度使用原生 dialog，期間停用遊戲操作。

日誌主檔不可讀時，改讀可用備份；只有可讀主檔才可輪替到備份。備份空間不足不阻止可成功的主檔保存，兩者都不可讀則禁止自動用預設值覆寫損壞資料。個別損壞的日誌列或舊 JPEG 不再阻擋其餘有效觀察、設定及原圖。照片的 JPEG 格式檢查共用同一個正式解析器。

## 獨立審查

Standards 初審發現救援匯出另寫一套較寬鬆的日誌驗證，會選中 `schema:999` 主檔而忽略相容備份。已改用正式 `readJournal`／`readVoyage` 驗證候選，同時保留有效原始快照；獨立重跑不支援版本及損壞容器兩種主檔，均選中完整備份，原 P2 關閉。複查明文規則違反 0、重要程式異味 0。

Spec 另重現單筆壞 JPEG 被日誌保留後，使攝影初始化整批搬移失敗，阻擋有效原圖。日誌與直接攝影初始化現以共用 JPEG 解析器逐列隔離壞值，原始 raw 日誌備份仍保留。獨立複查使用壞照片 101 與有效照片 102，確認 102 原始 bytes 保留、101 未遷移且後續拍攝 103 可用，原 P2 關閉。兩項獨立 P2 均已修正並複查；工作單仍維持 `in-progress`，不以本輪保存切片替代全作驗收。
