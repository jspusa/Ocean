# 0.18.10 帶路同行與深海渲染

基準 `bbfb7efecb35ceb754aa4adbbfa772fab64a3799`（公開 0.18.9）。本輪依 [規格](parity/ESCORT-v01810-SPEC.md) 修正正常自由探索時訪客掉隊、轉彎碰撞與保存續玩，並依實測追加深海岩壁／泥底的 fragment shader 特化；使用 AskMatt 的逐片 TDD 和獨立 Standards／Spec 審查。0.18.10 已公開發布，執行程式提交為 `e4a5985088c2eeabaaf1a805e73d3412c4a7a22e`；新版公開 20 分鐘探索已完成，全程記錄幀率 59.503 FPS；完整對等與商用驗收未完成。

## 已修正的玩家行為

訪客依玩家的實際速度及有界路徑連續跟隨。只有整段碰撞安全的捷徑才能省略轉彎，沒有每幀把訪客放回玩家旁邊。地面查詢和捷徑嘗試都有固定預算，不隨遊玩時間增長。右下角顯示簡短同行距離，暫停／照片模式隱藏；帶路完成仍須抵達目的地、同行並真正觀察指定生物。

保存支援全海域及最多 256 個剩餘轉彎點。舊版夾錯到海床底下、岩壁內或越界的訪客，僅在載入／續玩生命週期使用正式碰撞修復；合法 7,000 m 座標不被重新定位。未完成委託回首頁後保留原位置，續玩不重新生成；取消、完成和可領獎時結束同行。

## 觸控自然委託與橫向版面

公開站亦以相同自然流程完成 **31/31**，證據 `qa/parity/v01810-guest-public-touch.json`／`.log`，程序 exit 0。頁面版本 0.18.10，普通／加速最大同行距離為 3.50／3.55 m，包含直橫向提示與操作區無重疊、雙指環視游動、保存續玩、自然點選海龜並領獎；最終自動畫質開啟、品質 1、scale 1、GL error 0、無頁面錯誤。此公開流程仍使用同一電腦 GPU 的觸控模擬。

初次觸控測試的 CDP `touchEnd` 誤傳剩餘指頭，造成放開環視時反而抬起搖桿；修正的是測試，不是遊戲輸入。改成釋放指定手指後，加入每次環視仍維持搖桿的斷言，沒有放寬游泳門檻。與 [Chromium 原生多點事件已知差異](https://issues.chromium.org/issues/569778218) 一致；失敗紀錄保留為 `v01810-guest-local-touch`／`v01810-guest-touch-diagnostic`。

實際截圖另發現橫向入水提示遮到下潛按鈕。提示改放兩側操作區之間，最大寬度扣除實際左右安全區及右側兩按鈕；同行提示維持右下方。獨立版面驗證 `v01810-guest-touch-layout.json` 6/6 通過，涵蓋直向、橫向及 844／568 px 寬、左右安全區各 44 px／底部 21 px 的長提示 fixture，不能把這種瀏海模擬描述成實體 iPhone 驗收。

公開基準的後續診斷 `qa/parity/v0189-scene-diagnostic.json` 經真實 UI 入海並前往深海站，固定解析度 1843×1152、品質 2、4× MSAA、scale 0.64，各站採樣 15 秒及 3 個完整幀 GPU query。

最終程式只對 kind 0／material 16、17 的 fragment shader 將 `uKind`、`uMat` 改為常數。新兩種程式保留原始 vertex shader，既有四種特化不變；材質算式、幾何、LOD、光影、MSAA、解析度與動物內容不變。只預編譯一次，個別失敗回退至原始通用程式。早期同時特化頂點的方案未通過像素門檻；最終方案保持原始頂點程式，沒有放寬像素容許值。

最終證據 `qa/parity/v01810-trench-gpu-final.json` 使用同一 WebGL context 的 ABBA；每區塊 10 個暖機幀及 25 個完整幀 GPU timer query。固定相機、時間及每個 profile 的渲染設定，只開關新增兩種特化。下表為固定畫面的 GPU 耗時，**不換算實際遊玩 FPS**。
