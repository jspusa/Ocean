# 0.18.55 — transient multisample attachment lifetime

Implementation scope: after the existing complete colour/depth resolve, tell WebGL2 that the dedicated multisample source attachments are no longer needed. The resolved scene colour/depth textures remain live for volumetrics, post-processing, transparent shells, particles and photography. A subsequent successful frame fully clears the multisample source before drawing again. No shader, geometry, texture, sample count, resolution, simulation cadence or animal inventory is reduced.

This is an attachment-preservation hint. It does not free allocated renderbuffers, reduce resident geometry or establish physical-device FPS/power savings. Drivers may ignore it; benefit depends on the graphics backend. A software-GPU equality test alone cannot establish correct lifetime, because invalidation can legally do nothing.

## Contract and primary sources

The intended call is immediately after `blitFramebuffer`, inside the existing MSAA branch, with `READ_FRAMEBUFFER` and only `COLOR_ATTACHMENT0` / `DEPTH_ATTACHMENT`. At that point READ owns the transient multisample source and DRAW owns the resolved scene. `FRAMEBUFFER` aliases DRAW here and would invalidate live post-processing inputs. No additional bind, query, fence, flush or finish is needed.

- [Khronos ES 3.0.6](https://github.com/KhronosGroup/OpenGL-Registry/blob/main/specs/es/3.0/es_spec_3.0.pdf), sections 2.1 and 4.5: ordered commands; allowed targets; contents become undefined rather than zero or deallocated.
- [Khronos reference](https://github.com/KhronosGroup/OpenGL-Refpages/blob/main/es3/glInvalidateFramebuffer.xml): multisample data after a resolve is an explicit intended use.
- [ANGLE performance fixture](https://chromium.googlesource.com/angle/angle.git/+/HEAD/src/tests/perf_tests/MultisampleResolvePerf.cpp): the same resolve-then-invalidate READ pattern for attachment-store decisions.
- [Apple tiler guidance](https://developer.apple.com/library/archive/documentation/3DDrawing/Conceptual/OpenGLES_ProgrammingGuide/Performance/Performance.html): regenerated depth/stencil/multisample contents need not be stored for the next frame. Native GLES advice supports the intent, without proving a particular WebGL device benefit.

## Further diagnosis

The v0.18.54 public six-frame software-WebGL smoke retained one region request timeout at the headers continuation check and two ambiguous aborted requests. Its logs could not distinguish network latency, delayed browser execution or cleanup cancellation. The original receipt is preserved. The first bounded external timeline attempt retained a partial receipt after its two-second collection call timed out; it had included synchronous GL queries. A second frozen runner removes those queries, preserves the same game deadlines and keeps GL status explicitly unobserved. It completes six actual software-WebGL frames with no record overflow.

All 93 scene requests (one index and 92 unique chunks) have one-to-one early fetch observations; no request predates the hook. Observed scene reads complete in 178.2–556.2 ms, native headers in 171.074–456.972 ms; mapped native-header-to-JS-read-start gaps are at most 0.525 ms. The missing-required and pending-job sets are empty at the snapshot, with no scene timeout, page/console error, native loading failure or full-world fallback. Five observed function hashes match exact v0.18.54 Git sources. An optional texture request begins about 54 ms before close with no recorded terminal event; it remains censored rather than labeled successful or canceled. An observed 6,034 ms long task lies outside the wrapped render/upload/resize spans and is not attributed. Phase durations overlap and cannot be added.

This run does not reproduce the original warning. Changed network conditions and instrumentation prevent assigning a cause or claiming that query removal fixed the game. The collector changed; production network code did not. These are software-browser diagnostics, not physical-device FPS or power measurements.

The slow-reef colour-contribution probe found only 62,858 of 1,194,388 main-surface triangles on generic material programs (5.26%). Its largest remaining generic group, brain coral `0:4`, affected 249 of 12,288 final pixels (2.03%) in the selected view. This is contribution coverage, not fragment-invocation cost or a speedup. Additional specialization is deferred without measured benefit.

Global dynamic mesh unpinning is also deferred: aquarium clones share source GPU buffers, and moving actors/diver transitions can introduce new readiness waits. Retaining the existing owners reduced sampled startup transfer savings to 81–253 KB; a safe ownership design and transition evidence would be required before shipping.
