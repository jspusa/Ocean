# 0.18.33 音效載入熱修復

玩家回報卡在「準備海底聲景」而無法入海。以公開版本 f70cb3b 為基準獨立修復，不包含尚在製作的深海生物改版。

## 原因與修正

載入流程無期限等待原生 `AudioContext.suspend()`；音效預備期間失焦，又會等待原生 `close()`。任一 Promise 不結束便無法顯示開始按鈕。

音效預備現在使用 1,500 ms 上限，成功、失敗與逾時都清除計時器。失敗或逾時先同步卸除未使用的音效圖，再於背景關閉舊 context；失焦清理也不阻擋載入。真正點開始仍在原使用者手勢中啟用聲音，沒有新增自動播放、音樂下載或首頁週期工作。既有存檔與自動畫質保持原流程。

## 驗證

- 原生 Chrome 的 `suspend-hang-late` 在未修正版本重現載入不結束：到達音效階段後 5 秒仍未 ready。修正後桌機／觸控模擬均通過，包含正常開始、實際游動、兩條原創配樂輸出，以及舊 Promise 晚完成後新播放圖保持不變。
- 105／105 既有 CPU suites 一次通過，沒有重試；包含音訊路由、本機音樂競態、啟動與保存恢復。
- 68／68 靜態封裝檢查通過。
- 原生音效生命週期最終合併 18／18 情境、190 項檢查通過。初跑 12／18 通過，另六項在 macOS Chrome 恢復原生視窗焦點的測試步驟失敗；其載入斷言已通過。補上原生視窗最小化／還原後，僅重跑該六項並全數通過。沒有偽造 DOM 焦點事件或放寬 user-activation 斷言；初次失敗紀錄保留。
- 原生正式 UI 音效流程在桌機／觸控模擬皆通過，包含預備圖重用、聲音關閉偏好保存與重載、正常入海、設定中重啟聲音，以及第二分頁的存檔所有權阻擋。
- 兩位獨立代理的 Standards／Spec 審查均無需修正的 finding。固定部署基準 `f70cb3b`，候選快照 `a3a8ed6`，測試焦點修正快照 `796d3a9`；皆採 three-dot diff。原始音效邊界、存檔所有權及原生操作斷言保留。

主要本機證據位於 `qa/parity/v01833-audio/`：`suspend-red.json`、`suspend-green.json`、`lifecycle-final.json`、`lifecycle-combined.json`、三份 `*-final.json` 定向重跑、`cpu/results.json`、`static.log`。該目錄是本機測試產物，不屬於網站公開資源。

## 驗證界線

原生 GPU 為本機 Chrome／Apple M3 Max。觸控情境採瀏覽器模擬，未宣稱已在所有實體手機或音效裝置驗證；也沒有由本次測試推論新的 FPS、耗電或商用完成結果。正式 UI 音效流程及公開部署回執由發布後紀錄補充。
