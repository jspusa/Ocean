# 0.18.54 — bounded cetacean fragment specialization

This release adds one precompiled surface program for cetaceans (`kind=9`, `material=0`). Its vertex shader is the complete original `VS`. In the fragment shader, only the declarations of `uKind` and `uMat` become their corresponding constants; all shading, species/profile logic, LOD discard and other arithmetic remain unchanged. Unknown pairs and a failed device compilation retain the generic program. Selection never compiles during a frame. There are twelve base programs and, only when its assets are ready, the independently owned thirteenth imported-fish program.

No authored geometry, texture, animal inventory, collision rule, LOD distance, resolution, MSAA, adaptive policy or simulation/render cadence is reduced. The source change requires a full verified scene build even though no geometry recipe is edited. The full build completed successfully. The compressed world archive is byte-identical to v0.18.53 (SHA-256 `d39f92bd48b060f0499094f1b92f2c6da527b1fa5a5949709fac52a4d901367c`): 25,296,584 compressed / 66,444,704 decoded bytes, 509 batches and 3,729 shared nodes. Growth placements, limits and content stamp are unchanged; only their recorded source provenance changes for the edited engine.

## Measured candidate and limits

The scratch same-context comparison starts from the unchanged v0.18.53 engine (SHA-256 `d59482eaa68681176e84f34d59b27cfa99b744ca9f42b458407955d08a9f1ad6`) and injects the candidate shader through a temporary renderer wrapper. It uses actual `orca-001` at time 8, with an explicitly reset three-metre broadside diagnostic camera and complete streamed frames. A fresh unchanged generic shader must first match the original program byte-for-byte in the framebuffer. The specialized program keeps the exact attached vertex source and restores the original fragment source when only the two constant declarations are reversed. The actual orca must be submitted; drawings, geometry, shadows, uploaded data and residency must match.

Both pipelines warm before three alternating complete-frame GPU-query pairs per profile. All samples are retained; disjoint samples fail. Pixels are read immediately before yielding, and every RGBA channel must remain exact. Software-GPU identity, compilation and first-use costs are separately recorded; steady measurements exclude shader preparation.

These are SwiftShader complete-frame timings in one controlled near-orca view, with three samples per mode/profile. They are not native hardware GPU results, display FPS, battery measurements or a guarantee for another scene/device. All six comparisons per profile retain exact RGBA and unchanged render work.

The production CPU regression first fails on the stock generic route, then passes 13/13 with the new route: exact original VS and selector-only FS, interleaved cetacean body/profile/gesture/lighting state, twelve bounded base programs, compiler-failure fallback, unknown-pair fallback and no render-time compilation. Renderer-efficiency checks pass 12/12. The old immutable uniform-submission snapshot retains a 6/7 active-hash failure on both untouched v0.18.53 source and the candidate in this environment; its fixture is not rewritten, and this release does not claim every historical repository test is green.

## Rejected CPU candidate

A squared-axis broad-phase experiment preserved all three ordered residency sets and passed 54 time/profile/quality cases with real streamed geometry. Large Node VM timing improvements did not survive the native browser check: full steady-update medians were reef 0.0328 → 0.0324 ms, offshore 0.0418 → 0.0418 ms and hadal 0.0344 → 0.0336 ms; pure reef selection regressed. It is not shipped. The timing fixture used a fixed stream clock, native elapsed clock, actual resident geometry and no renderer calls; no FPS claim is made.
