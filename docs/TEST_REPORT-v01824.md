# 0.18.24 深海獅子魚游動光影

基線 `7b4961e7979593cf6e88b4236b601a5530284587`；[規格與診斷決策](parity/SNAILFISH-LIGHT-v01824-SPEC.md)。本輪驗證進行中，公開交付另驗；完整商用目標持續進行。

## 修正範圍

獅子魚尾波的法線原本只包含正弦波斜率，漏掉振幅包絡的導數；胸鰭拍動也沒有更新法線。本輪在同一頂點 shader 內依位移順序套用兩次 inverse transpose，讓表面方向跟隨實際形變。片段 shader、光源、tone mapping、配色、模型、尺寸、地形、個體位置、原位移方程與自動畫質不變，沒有增加 pass、貼圖或幾何。

原生 GPU transform feedback 使用實際 Renderer 建立及選中的 colour／shadow programs，從附掛來源原樣重鏈；以實際高低模上的 20 個局部切平面、八個相位，對 GPU 輸出位置做中央差分作 oracle。含半步收斂、靜態控制及逐階段 GL 檢查；沒有在測試中複製位移公式。

| 同一原生 GPU 驗證 | 原程式 | 修正後 |
|---|---|---|
| 406 項檢查 | ★☆☆ 158 通過 | ★★★ 406 通過 |
| 靜態控制 | ★★★ 40／40，GL=0 | ★★★ 40／40，GL=0 |
| 形變法線最大方向誤差 | ★☆☆ 約 6.400° | ★★★ 約 0.001827° |

星星表示本項驗證結果，不是整體畫質或商用評分。3,600 筆跨版本位置輸出有 144 筆胸鰭樣本呈 Float32 差異，最大座標差 `3.7253e-9 m`、距離差 `4.5626e-9 m`；靜態輸出相同。原位移方程不變，但沒有宣稱 GPU 位置逐 bit 相同。

證據封存於 `qa/parity/v01824-evidence/rig-valid-red.json`、`rig-green.json`、`positions-comparison.json`。首次 `rig-red.json` 因測試未正確綁定片段 shader 取樣器而出現 GL1282，屬無效負例；已保留且未列入上表。修正獨立、完整紋理與型別後才取得有效 RED，沒有更動實際 shader 來源或放寬容差。

## 正常探索與曝光診斷

原版 0.18.23 經可見介面沿海流到 7,001 m，再以原生游泳／指向選取同一獅子魚，使用既有相機設定 0、−0.5、−1 EV、25° 視角、f/16 及自動對焦，真快門原 JPEG 由正常相簿解碼。自動畫質開啟、scale 1、2560×1600 framebuffer、`floatColor=true`，實際高模 drawCount=1、低模=0，拍攝距離約 1.65–1.61 m。

0 EV 近圖已可辨小眼、粉白漸層、胸鰭分葉及部分鰭條；較暗原圖的個體 yaw 同時改變約 0.415 rad，不能將差異全部歸因曝光。這組不能證明 RGBA8 截斷或 LOD 問題，也不足以支持增加新的材質減光係數。因此本輪只修正已重現的形變法線；均勻皮膚及有限的透明組織近似仍是擬真品質欠帳。

三張原 JPEG 及全部姿態／相機紀錄：`qa/parity/v01824-evidence/normal-baseline/`。第一次正常測試抵達海底後因隱藏首頁與選單的同名相機按鈕導致測試定位器歧義，已保留為 `normal-baseline-selector-failure/`，修正為面板內定位器後完整重跑；不是遊戲故障。

## 受控畫面與 GPU 成本

同一台 Apple M3 Max／原生 Chrome，以同一 context 與實際 renderer，切換由固定基線原始建立函式編譯的 generic、八個 surface 及 shadow programs；驗證 20 組 attached VS／FS。只允許 VS 差異，其他 shader、資源、幾何、個體及品質固定。每端九場：四個獅子魚側面／斜前方姿態，另有海豬、吸血烏賊、灰姑娘海蛞蝓、鸚鵡螺和礁區五個控制場景。

每端兩個計時場景，各 ABBA 四塊、每塊十次暖機與25次完整 render query，共200個原始樣本。所有計時完成後才讀取畫面。保留全範圍 raw samples、有正負號的結果與 PNG／RGBA hash，不將計時當正常遊玩 FPS。

| 固定場景 | 桌機 GPU 中位數：原 → 新 | 觸控尺寸 GPU 中位數：原 → 新 |
|---|---|---|
| 獅子魚近景 | ★☆☆ 5.0271 → 4.9772 ms（−0.99%） | ★☆☆ 2.5569 → 2.4867 ms（−2.75%） |
| 礁區控制 | ★☆☆ 13.8348 → 13.8544 ms（+0.14%） | ★☆☆ 5.2200 → 5.0792 ms（−2.70%） |

一星表示單機受控證據，不是畫質評分。未改變的控制場景也有波動，不能把微小差異當普遍加速、實體手機或耗電改善。兩端共36張 PNG，八組獅子魚畫面出現預期局部光影變化；十組控制場景完整 RGBA 相同，各版本重複影像也相同，所有 GL=0、errors=[]。兩端均保留原預設 quality（桌機2／觸控1）、scale 1、原始尺寸和內容。

首次桌機 fixture 在白天09:00要求繪製夜行鸚鵡螺，因原有生態排程而失敗；沒有強制可見或刪掉該案例。最終先完成全部日間計時及影像，再經實際研究台「準備夜潛」至21:30，最後確認夜間鸚鵡螺原個體確實提交。完整日曆、排程、姿態及解析度保持在各自ABBA之間一致。失敗報告仍封存於 `light-desktop/`；正式證據為 `light-desktop-final/`、`light-touch-final/`。
