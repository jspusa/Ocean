# 0.18.9 匯入中斷恢復與日誌備份

基準 `1e16816b33b4c2947139133be5a1345d361cbf7e`（已發布 0.18.8）。延續 [保存工作單](parity/issues/01-save-and-lifecycle.md) 與整體商用目標；不以本輪代替完整功能、實體裝置或真人驗收。

## 玩家要求

1. 已保存的航程、圖鑑、設定、照片原圖及已投稿附件，在匯入期間關閉／崩潰後不能混用新舊版本。未完成的匯入於下次啟動恢復匯入前資料；只有全部資料完成保存才算匯入成功。
2. 在同一 IndexedDB 交易內保留完整舊照片及四個 localStorage 原始快照，再替換照片。恢復紀錄在新航程與日誌完成保存後才可刪除；刪除交易完成為匯入提交點。容量不足必須中止交易，舊資料保持可用。
3. 啟動先取得既有分頁使用權，再處理未完成匯入，最後才讀取日誌、分配 GPU 或執行功能遷移。恢復先寫回 localStorage，最後以單一交易還原照片並刪除恢復紀錄；重複中斷可安全重試。
4. 恢復失敗、版本不支援、資料損壞或外部分頁改寫時，停止啟動與後續保存，保留紀錄並顯示可用的重新讀取／完整備份入口。啟動前的匯出必須來自持久恢復紀錄，不能匯出尚未載入的預設航程。未知外部值不自動覆寫。
5. 重開後的恢復包含完整原圖及投稿引用；匯入備份中的待救援照片也不能因重開而消失。現有記憶體救援與唯讀匯出保留。
6. 日誌主檔不可讀時讀取可用備份。只有可讀的主檔可輪替到備份；備份空間不足不阻止主檔更新。沒有可讀資料時禁止自動把預設值寫回損壞主檔。單一壞的日誌／照片列不影響其他有效資料與設定。
7. 離頁等待涵蓋啟動恢復及匯入；不能在其仍可寫入時釋放鎖。一般攝影操作不能跨過尚未解決的恢復紀錄。既有存檔、自由探索、指標選取與桌機／觸控自動畫質保持可用。

## 實作與驗證界面

沿用 [既有規格](parity/SPEC.md) 確認的真實瀏覽器操作、正式保存／讀取函式及瀏覽器 Storage／IndexedDB 失敗邊界。先重現目前中斷後混用資料，再逐段加入實作及回歸。真正 renderer crash／重開測試覆蓋照片提交後、各 localStorage 寫入後、完成提交後及恢復過程；只丟出例外不算崩潰恢復證據。

照片資料庫保留名稱與 records 格式，版本升為 2，使用獨立恢復 store，避免一般照片清除操作刪掉恢復資料。恢復紀錄保留舊值及計畫新值，只有目前各 key 符合其中之一才可自動還原。外部未知變更、瀏覽器主動刪除網站資料、裝置損毀及底層儲存硬體故障不由此協定偽稱已解決。

Standards 與 Spec 獨立審查後提交、發布並核對公開檔案與實際啟動。完整工作單仍依全部要求判定，不提前關閉。
