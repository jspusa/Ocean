## 正式行為及測試邊界

高更新率螢幕的 RAF 不再要求每次都更新及繪製整個場景；潛水及互動觀賞以約 60 次／秒為提交上限，無操作首頁約 30 次／秒。這是工作排程政策，不是裝置 FPS 或耗電承諾。固定步長物理、真實時間、輸入與自動畫質的 CPU 時間軸檢查已通過；刻意降低首頁提交頻率不能污染潛水量測或誤觸自動降畫質。

手把 B 明確選取畫面中央的附近生物，使用真實選取幾何，來源保持主動操作的 `key`；滑鼠、觸控、鍵盤指標選取維持既有語義。新增正式 `pollGamepad` 路由與投影案例，舊版在滑鼠先指向旁邊魚後選到旁邊個體的 RED，修正後中央個體 GREEN；包含按住不重選、空水清選與偏移直式 canvas。這是控制器輸入 adapter 證據，不是實體手把驗收。

調查冊與摘要的「追蹤此調查」為明確選用。啟用後完成測點便改指下一測點、生物棲地與回收位置，現地完成後清掉舊路標並提示回首頁；正式回報後結束追蹤。手動改標記或停止追蹤會解除調查對路標的控制，即使手動指定與舊目標相同也不會擅自繼續。僅閱讀另一冊頁不改路標。

追蹤只在原 `features.story` 保存 `null`、`story` 或 `hadal`，舊存檔預設關閉；讀檔檢查相符調查已接下且未完成。正式 feature lifecycle／UI 處理器、正式路標函式與存檔 adapter 的三個 RED→GREEN 切片及擴充涵蓋逐點更新、重載、手動覆寫、兩冊歸屬、完成後回報與無效資料。`hadal-story.cjs` 目前 12/12 通過。鍵盤焦點 fixture 原只擷取單行 `markPlace`，已納入新的正式路標函式，保留原焦點斷言，23/23 通過。
