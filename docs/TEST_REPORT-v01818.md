# 0.18.18 手把工具指標

固定基準 `c0a5fbe8a1ca71309e3c86864e8ac71327ceb574`。本輪依 [工具指標規格](parity/GAMEPAD-TOOLS-v01818-SPEC.md)，補齊標準手把對既有工具的操作；完整商用／Wii 功能目標仍在進行。渲染器、地形、生物配置與自動畫質預算沒有新增特效或提高負載。

## 正式輸入與取消

View／Select 進入指標，左搖桿移動、A 點選／按住拖曳、右搖桿捲動、方向鍵調整選項，RT 精細移動，B／View 返回游泳。工具共用滑鼠與觸控的正式處理器；虛擬捕捉由指標模組管理，原生 pointer ID 仍交給瀏覽器。所有生成事件維持 untrusted，不能當作瀏覽器授權手勢。文字、檔案與其他原生輸入會顯示接手提示。

取消在面板／工具／首頁／照片狀態改變前執行；原生鍵盤與指標接手監聽先於遊戲處理器，避免 Esc 提前提交半筆。斷線、背景、失焦及顯示環境遺失會取消手勢，重返控制須先放開按鍵。手把 API 出錯會清除原控制器移動，沒有使用指標時不清除觸控搖桿。

## 逐項測試

正式指標模組與 DOM／時間系統邊界以 17 個行為逐項 RED→GREEN，涵蓋輸入消耗、點選／拖曳、原生／虛擬捕捉、取消順序、30／60／120 Hz、精細移動、Start 交接、方向鍵、range、捲動與原生控制項提示。`qa/parity/v01818-pointer-*.log` 保留失敗與修正證據。這些是 CPU 行為證據，不能替代原生瀏覽器工具鏈。

正常游泳與選取的 fixture 改載入正式指標模組；水面操作經正式航程 guard 與照片恢復流程啟動。針對性檢查選取 18/18、水面／輸入 15/15 通過。完整打包回歸、原生工具流程與公開發布結果待下文按實際執行補記。

獨立審查另外找到兩個輸入整合問題並補 RED→GREEN：虛擬事件可讓既有移動控件重新寫入軸值，因此在派送結束後以 finally 清零；指標進入／消耗輸入時釋放舊手把移動持有狀態，避免中立控制器清掉後續原生觸控。這兩項納入上述 17 個行為，完整來源為 `v01818-pointer-control-axes-*` 與 `v01818-pointer-ownership-*`。

## 驗證範圍

瀏覽器 runner 使用原生 Chrome 與預設自動畫質，僅替代標準 `navigator.getGamepads` 輸入來源；透過正式 RAF 與可見 UI 操作。讀取與來源控制使用 CDP `userGesture:false`，正常入海的一次真實點擊另外記錄。沒有寫入位置、時間、信任或進度來跳過玩法。這是桌機上的控制器模擬，並非實體手把或手機驗收。

初始入口 RED 證明 View／Select 尚無可用游標，前置的原生 GPU、自動畫質與正常入海／可寫航程均成立，沒有 page errors。證據 `v01818-gamepad-tools-entry-red.json/.log` 及失敗截圖保留。

## 原生畫筆首次完整流程的實際發現

入口 GREEN2 7/7 通過，能以手把沿正式選單啟動筆、A 拖曳寫入世界座標，沒有同時游動或拍照。首次入口 GREEN1 是 runner 把可見頂欄誤判為需捲動，屬測試導航錯誤，原失敗紀錄保留。

第一輪完整畫筆流程通過 15 項，包括五色、撤銷、投影命中擦除與 Done 保存，但暫停按鈕入口失敗，因此整輪仍是 failed。定位為正式指標 hit-test 把按鈕內 aria-hidden 裝飾 SVG 當成不可點擊；改為先驗證實際互動祖先，對裝飾子節點回到可見按鈕。新增 RED→GREEN 同時覆蓋停用／隱藏控制項不可穿透；納入上述 17 個行為。`v01818-gamepad-tools-pen-green1.*` 與 `v01818-pointer-decorative-*` 保留此證據。最後重新載入與繪製實例檢查另跑，不倒填到這個失敗流程。

最終本機畫筆流程 **18/18** 通過，包含正常 renderer frame 前進、真實 inkSegments／動態實例／drawCount、五色、撤銷、擦除、Done、返回首頁及重載後逐點一致。暫停按鈕實際仍命中 aria-hidden SVG，修正後正常開啟選單。證據 `v01818-gamepad-tools-pen-final.json/.log`，errors=[]。此輪未寫入位置／時間／信任或強制 render。

額外類比輸入回歸：扳機 value=0.3 但 pressed=false 仍須等到回到中立才恢復游泳，避免離開指標時殘留上浮／下潛。正式模組 RED→GREEN 加入上述 17 項，證據 `v01818-pointer-analog-neutral-*`。

取消操作最終本機流程 **14/14** 通過：A 拖曳後原生 Escape 與 Start 均取消草稿、保存筆數不變，Start 仍正常暫停；經正常返回海中且自然 frame 前進後，繪製實例回到原提交筆數。初跑把暫停時保留的舊畫面當作即時草稿提交而失敗，原始 failed 證據保留；未強制 render 或改弱保存斷言。最終 `v01818-gamepad-tools-lifecycle-final2.json/.log`，errors=[]。

觸控表面的輸入交接 **15/15** 通過：手把指標按住實際上／下／左搖桿不洩漏角色位移或軸值，B 退出時半按扳機持續等待，歸零後新按扳機可浮潛；普通手把泳行及真正 CDP touch 接手後中立控制器不清除移動，放開 touch 後停止。證據 `v01818-gamepad-tools-containment-final2.json/.log`，errors=[]。舊右環視搖桿在現行手機 UI 隱藏，因此不偽造顯示來宣稱已驗；手機正式環視使用拖曳海景，操作說明同步修正。初次 runner 要求舊控件可見而失敗，原證據保留。這仍是桌機 Chrome 觸控模擬，非實體手機。

## 自然生物流程的失敗紀錄與續玩

使用專屬 `/tmp/ocean-v01818-natural-profile-20261026-a`，由正常新航程開始。每次重試沿用同一瀏覽器實際玩得的保存，不注入存檔；報告記錄原始航程、前次保存與本次入口的一致性。前五輪均維持 failed，不能因部分互動成功計為整輪通過。

- 第 1 輪推進控制在移動目標外提前收斂，未抵達 1.7 m；修正 runner 推進量，抵達距離與產品規則不變。
- 第 2–4 輪選取成功，但操作期間海豚持續游動；第 4 輪讀回距離 6.35 m，超過正式 5.2 m 接觸範圍，所以輕撫入口正確隱藏。runner 改為正常追近再操作，沒有放寬範圍或凍結生物。
- 第 5 輪兩次正式來回手勢已保存 trust=12、strokes=2；動物離開範圍使手勢目標消失，runner 錯把自然離開視為致命錯誤。後續只在確認目標已隱藏的此種情況釋放按鍵並重新靠近，其他錯誤仍失敗。

原始紀錄為 `v01818-gamepad-tools-nature-training1` 至 `nature-training5` 的 JSON／log／截圖。後續完成結果另記，不覆蓋這些失敗紀錄。

第 6 輪正常完成招募、哨子、抓握／放手、船邊到位及嘴部連點旋轉，但來回輕撫未加入訓練佇列，整輪仍為 failed。定位到正式產品以單次事件水平位移大於 2 px 才更新方向；平滑搖桿及 RT 精細移動在 60／120 Hz 的單次位移可能不足門檻，累計路程已足仍不計反轉。水下撫摸與甲板訪客也使用相同模式。這是產品問題，不能用加快測試動作或關閉精細模式避過；修正與回歸另記。

三處手勢改從水平極值累積反向超過原有 2 px 再計轉向；保留各自接觸範圍、總路程、持續時間、冷卻、跳步取消與獎勵保存。水下／訓練共用模組內 `trackStroke`。正式領域回歸 **ecology 44/44、ship 18/18**，包括同路徑 30／60／120 Hz、RT 精細速度、微小抖動、短／快手勢、越界、取消及六種訓練手勢。訓練、水下與甲板均先取得舊程式 RED，再取得修正 GREEN；水下／訓練紀錄為 `v01818-ecology-smooth-*`，甲板首次 RED／GREEN 僅保留本輪代理工具輸出，沒有另存歷史 log。最終整套執行另保留 ship log。原生訓練與 RT 甲板互動仍按同樣的平滑動作重驗，不能以 CPU 結果代替。
