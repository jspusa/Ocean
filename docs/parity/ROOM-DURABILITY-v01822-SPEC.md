# 0.18.22 房間服務重啟恢復

固定基線 `7c8d672b9e5b6184bc2e7f07c0ca221654670c9f`。承接 [完整多人計畫](MULTIPLAYER-IMPLEMENTATION.md) 的可靠准入與正式服務基礎；不是持久好友系統，也不縮小 Stage B、D、E 或整體商用範圍。

## 行為契約

1. 明確設定 `OCEAN_STATE_FILE` 的單程序 Node 房間服務，以本機 SQLite 保存短期房間權威。成功回覆的建房、申請、批准／拒絕、訪問開關、取消、離房、世代交接與確認撤銷，都須在回覆前完成交易。未設定時保留原有記憶體模式，不默存使用者資料。
2. 在服務被 SIGKILL 後，以同檔案、同內容版本重啟，期限內的客戶端可恢復原房號、epoch、memberId、角色、訪問設定、未過期等待申請及旋轉證明；不新增席位、不重新批准。初次 joined 或旋轉 joined 遺失後仍可用完全相同的原證明恢復。已撤銷、拒絕、取消或離房的權利不得因重啟復活。
3. 磁碟只存摘要，不存 admissionNonce、resumeNonce、resumeToken 或完整恢復請求。保存上限與房間／申請上限一致；不存私人照片、個人進度、訊息歷史、socket 或高頻姿態。重啟後所有成員先呈現離線、pose=null，直到新連線送來新姿態。
4. 所有原本固定的 admission、pending、resumeRetry 截止時間跨重啟保持不變。存活連線每 5 秒最多更新一次 30 秒席位租約；崩潰後只使用最後成功保存的截止時間，重啟本身不續租。已斷線者仍沿用偵測斷線時的固定期限。時鐘倒退到早於保存時間時拒絕啟動，不重設時間挽救資格。
5. 一般 pose 不逐包寫磁碟；但第一個已驗證的當前世代操作若撤銷恢復證明，即使後續業務判定失敗，也必須先保存撤銷。訊息額度跨短暫重啟保留，位置與暫時訊息不歷史重播。
6. 同一檔案只有一個 writer；第二程序無法取得鎖時不得開始監聽。正常關閉及程序被終止會釋放鎖，不依賴易失效的 PID 檔。檔案損壞、內容／格式版本不合、超出容量、無效關聯或讀寫失敗都不得默默以空資料覆蓋。
7. 若 commit 失敗或結果不明，當次任何成功事件均不送出，整個權威停止處理、關閉連線，health 回報不可用。不得繼續使用尚未提交的記憶體狀態。正常服務關閉保留未過期資格，不等同主持者正常離房。
8. 公開網站仍使用既有端點設定與自動畫質；本輪不假設取得後端帳號，不連公共中繼、不提供假公網驗收。SQLite 檔案 adapter 支援單一主機的本機檔案系統；未實作多主機共享資料庫或 Cloudflare Durable Object adapter。

## 驗證範圍

沿用完整計畫已確立的 HTTP／WebSocket 與正式 CLI seam，以真實獨立子程序、連線、SIGKILL、同檔重啟驗證。各行為逐項 RED→GREEN；不能修改內部 room Map 或直接寫入資格來取得准入。資料檔及旁檔檢視用於明文秘密／權限診斷及刻意製造損壞的拒絕負例，不作成功恢復的替代證據；成功資格、過期與恢復結果仍由正式網路介面判定。必要的儲存失敗 adapter 只注入 IO 失敗，結果仍由公開連線、ACK 與 health 判定。

既有房間與客戶端測試全量回歸。真程序崩潰不等於設備斷電、硬碟故障或跨區複寫驗收；公開靜態發布不等於多人後端部署。正式商用及工作單 11 維持未完成。

## 技術依據

使用目前環境的 [Node 24.18 SQLite](https://nodejs.org/download/release/v24.18.0/docs/api/sqlite.html) 原生同步交易與 [SQLite PRAGMA](https://www.sqlite.org/pragma.html) 的 locking_mode、journal_mode 及 synchronous 設定；採用終身 EXCLUSIVE writer、DELETE journal、EXTRA 同步與 macOS fullfsync。這些是保存策略，實際驗收仍以本輪執行證據為準，不宣稱全檔案系統或真斷電已測。
