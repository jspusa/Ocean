## 生物學依據與美術設定

[NOAA Fisheries：Green Turtle，Appearance](https://www.fisheries.noaa.gov/species/green-turtle) 說明背甲中央五片盾、兩側各四片，背甲為深褐、灰或橄欖色，腹側為較淺的黃白色；眼睛之間另有兩大片鱗。這些是本次分區和色彩的依據。來源也提到幼龜可以有斑駁或放射狀圖案，因此本次不是宣稱所有放射紋都不真實，而是修正所有盾片完全相同、細密高對比的程式化圖案。

盾片具體比例、接縫寬度、磨耗、粗糙度、皮膚色斑與頸部輕摺痕仍是原創美術設定，沒有假稱為實測個體表面。沒有下載或發布來源照片。

## 根因與窄範圍設計

`make_textures.py` 的現有資產其實已放入五個中央與兩側各四個 seed；主要問題是最近點分區加上每片一致的 `sin(angle*65/123)` 放射紋和 `sin(radius*300)` 圓圈。只覆加 noise 仍會留下這個主導外觀。

此次採 shader-only 修正：完全替換 `src/engine.js` 的 `uMat==5` 材質場，不再讓舊 `uShell/uShellN` 圖樣參與海龜著色；既有資產、紋理載入契約與其他材質保持原有資源。新 helper 放在 `float visibility(vec3 n)` 前；不修改共用 `triNormal` 或頂點動作。

背甲以 `q=((local.x+.16)/1.0, local.z/.70)` 定位：兩條連續彎曲縱縫界定中央帶，帶內四條非等距橫縫產生五盾；兩側各三條錯位橫縫產生四盾；橢圓邊界另界定窄邊緣區。這是有限的距離／分區運算，不做每片段 35 個 seed 搜尋。細節以局部座標與既有 `vGenes/vTint` 定義，所有 LOD 與時間共用同一個個體圖樣。

皮膚不用世界法線決定投影平面，額部大鱗限制在實際兩眼之間的局部範圍。腹甲和喙共用 tag 3，因此只在 `local.x<.95` 的身體區域施加腹甲紋理；現有腹甲最大 x 約 .84，喙最小 x 約 1.166。眼睛 tag 4 保留。

微小高度的表面梯度使用 `vRelative` 的螢幕導數和已變形的法線；退化或極小投影回傳原法線。`materialSurfaceNormal(normal,rawHeight,strength)` 先對原始連續高度求一階導數，再套用像素足跡的強度衰減；高度本身不能含 `fwidth`、`skinLine` 或其他導數運算的結果，避免 GLSL 未定義的高階導數。細紋依像素足跡漸退，最低品質可省去微法線，主要分區與個體色彩不能隨品質改變。保留已通過驗證的 tag 2 鰭變形與逆轉置法線；本 slice 不改幾何、UV、尺度、UID、路線、碰撞包絡或自動畫質控制。

預算目標：零新增三角形、draw call、紋理資源與每幀 CPU 更新；每片段有限分區距離、至多兩層連續 noise，只有窄外緣需要角度分段。實際 GPU 成本須由正式渲染量測，不以原始碼行數宣稱效能提升。

## 有效驗證與尚未完成的工作

1. 使用正式 VS/FS、實際海龜三角形與現有紋理，先重現相同局部表面在剛體旋轉後 base 改變／法線不協變的 RED；修正後驗證 base 保持、法線正確旋轉。不能複製一份新公式來自證。
2. 固定同一個體、相機、時間與曝光重新擷取上述七角度，實際檢視木紋磁磚和亮蜂巢是否消失，腹甲和喙是否分開、頭部兩鱗是否位於額部。顏色數值落在某個區間不代表通過。
3. 在正式高／低模型、划鰭、轉向及品質變更中確認紋理不跳投影、不閃點，個體圖樣不變；保留既有 rigid shell/fin normal 回歸。
4. 維持桌機／觸控自動畫質流程，量測實際渲染成本；觸控模擬不等同實體手機耗電或效能驗收。
