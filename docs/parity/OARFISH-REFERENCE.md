本文件準備一個原創 **Regalecus glesne** 遭遇切片；不是實作、測試通過或發布紀錄。建議為一隻約 **4 m** 的個體，出現在下降至 700 m 中層站之前、約 **480 m** 的開放水域。模型、配色、動畫與縮圖須自行製作；來源只提供事實和觀察依據，不轉用來源照片、影片、網格或描述文字。

## 模型與體驗驗收清單（尚未執行）

1. **尺寸與輪廓。** 公開 `faunaGeometry` 的高／低模型均為有限頂點、法線、顏色及有效三角面；以吻端至尾端量測 4 m。側面呈細長帶狀，正面顯著側扁，尾端逐漸收尖；不能是一般魚或鰻魚模型直接拉長。高低模型保留一致的身體尺度與主要附肢位置。
2. **辨識部位。** 可見小口、小側眼、兩組前部冠狀延長鰭條、沿身體延伸的背鰭、小胸鰭及細長腹鰭；不添加臀鰭或巨大扇形尾鰭。冠與鰭根需接在身體上，不能以浮空線段代替。低模仍須從側面與斜角辨認主要輪廓。
3. **真正的鰭動。** 主體基準保持相對穩定，背鰭膜／鰭條呈沿長軸傳遞的波，而非整魚左右蛇行。鰭根不離體；顏色、深度／陰影及照片使用相符姿態。反面觀察不因剔除而整片消失；確定性測試和連續渲染分別驗證，不能只用一張截圖證明動作。
4. **直立全身包絡。** 頭朝上時，完整 4 m 軀幹、頭冠與腹鰭絲都必須留在有效水體。碰撞、視錐剔除、選取及相機焦點要考慮實際旋轉後的界線；不能只沿用水平魚的上下半徑。轉姿、路徑交界與 LOD 轉換不得瞬移、縮放或跳變，暫停／回首頁停止遊戲動作。
5. **銀色材質。** 在棲地原有暗水、頭燈開／關、側光與逆光中檢查；身體應有受光差異與細微斑紋，紅鰭受水下照明影響。不能用固定純白／自發光假裝金屬反光，也不能為讓牠可見而全域增亮深海。材質係數屬美術參數，沒有科學量測宣稱。
6. **自然到達與操作。** 從正式入海入口正常游至棲地，不搬動玩家或動物、不呼叫發現函式代替操作。桌面滑鼠及觸控尺寸各完成選取→觀察→真實快門；未選取時不新增遮住中央視線的名稱。遠離、遮擋、點空白及再次接近的行為沿用既有可見性與選取規則。
7. **完整取景與保存。** 4 m 的長身及頭冠可在桌面／觸控直橫向完整入鏡，特寫也不穿入模型。實際照片像素、物種／個體 metadata、圖鑑進度、重載／匯出匯入結果一致。若數位水族館提供該物種，另驗證獨立展示 instance、真尺度、直立包絡、取景、退出還原；不能把水族館程式存在視為本種已驗收。
8. **效能與證據範圍。** 一組共享高低模型、固定個體數，避免每幀重建網格／批次。比較加入前後的同場景、解析度、品質、MSAA 與連續動作，記錄 GPU 與幀時間，再另驗自動畫質；低畫質仍保留辨識輪廓與背鰭動作。CPU 幾何／路徑測試不能代替 WebGL 目視，自動觸控不能代替實體手機，局部通過不能宣告全面擬真或整體 parity 完成。

## 現有登錄、個體與場景相容性

以下來自上述基線的源碼閱讀，沒有執行模型、瀏覽器或建置。

- **追加種類，不插入舊集合。** `src/fauna.js:163` 的 `registerFauna` 同時追加 collection 和 `SPECIES`，本身沒有重複 ID 防護。現有登錄順序為原始 12 類、8 類小生物、7 類鯨豚、5 類 abyss、3 類 trench、2 類 pelagic、4 類 reef，共 41 類。`index.html:87–97`、`build.py:8`、`bake_scene.cjs:7` 順序須一致；新種類應在既有礁魚之後追加。若本切片只加一種，預期是索引 41；邏輯仍應按穩定字串 ID 查找。建議使用新的 `oarfish` ID 和獨立集合，實作前再確認無衝突，不插入 `ABYSS_SPECIES`／`TRENCH_SPECIES` 使後方數字索引位移。
- **舊 UID 和個體特徵都要保留。** `src/individuals.js:17–33` 依數字 species 索引及同種順序生成 `bioSeed`，依字串 species ID 加三位序號生成 UID；重排 registry 即使保住字串名稱仍會改變舊個體特徵。新 actor 要穩定追加，舊 actor 的物種、順序、UID、seed、home、尺度不變；保留 `fauna:true`，避免套用一般魚的隨機尺寸倍率。
- **登錄不等於生成。** `src/fauna_world.js` 只處理有對應 site 的 `FAUNA_SPECIES`；`src/trench_world.js:6–7` 則假設每個 `TRENCH_SPECIES` 都有 `OceanTrench.habitats[sp.id]`。不能只把條目塞進某個集合。世界模型、批次、遭遇與圖鑑須使用同一個註冊物種，不造只在圖鑑存在的魚。
- **三種載入路徑一致且冪等。** `src/app.js:472` 優先載入已編譯場景，失敗才呼叫程序 `addLife`；目前載入後另呼叫 `ensureReefFish` 再初始化個體。`src/scene_cache.js:34–38` 及 `src/scene_stream.js:159` 直接還原保存的數字 species 索引。皇帶魚須在 streamed、整包 compiled 與程序 fallback 都恰有預期個體；已烘焙場景包含牠時不可再次追加。追加需在 `initializeIndividuals` 與功能狀態 sanitize 之前完成。
- **不可直接套用水平魚的 pose。** `src/individuals.js:240–255` 的既有 trench／abyss 分派與一般魚姿態有限制；例如 trench 路徑將 pitch 壓在約 ±.04。新增行為須真正支援頭朝上，並沿用公開 `faunaMotionPose` 的世界／展示入口與 context。`src/fauna.js:154–157` 的正規化及 `modelBounds` 必須保留身體量測基準與伸出附肢的完整界線；不能用隱形極值點偽造尺寸。
- **保存與 UI 沿用正式資料。** `src/ecology.js:15–21` 用目前 live UID 驗證個體、用 species 字串 ID 保存筆記；先恢復狀態再生成新魚可能丟失其個體記錄。`src/fauna_world.js` 的 `animalFocusPoint` 已考慮 pitch；`src/aquarium.js` 從實際動態批次建立展示，再呼叫 `faunaMotionPose`。須驗證同一皇帶魚的選取、攝影、圖鑑及可用展示，而不是另造不相關 UI fixture。

本文件只建立研究依據與驗收方向。實際 home、模型三角形數、材質／動畫參數、LOD 距離、測試結果及發布版本應由後續實作報告記錄，不能預填成功。
