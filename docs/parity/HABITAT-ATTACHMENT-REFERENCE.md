## 實作邊界

- `reefAnemoneHabitat` 使用已送入渲染器的同一組高細節岩石幾何，經 `OceanRockContact.heightOn` 查詢真正三角面。每根觸手的底部各自貼合；沒有將所有珊瑚一起下移。
- `anemoneGeometry` 的可選根部高度 callback 保留無參數的原造型與亂數消耗。180 根觸手的頂點數與法線不變。小丑魚的中心取同一塊支撐面，仍是原來的 4 個 UID。
- 生長中的珊瑚配置會保留海葵周圍的小範圍空間；只有原本侵入該區的鄰近珊瑚需要重新選位。貼於岩石上的低矮薄層仍可共存。
- 沉船在製作實際船板及甲板時記錄支撐面。窄海扇放在完整船板頂部，具有多個根部的海綿與盤珊瑚放在完整甲板。最終高度仍由 `surfaceAt` 對船體三角面取樣，查詢上限避免把下層甲板錯貼到上層屋頂。
- 沉船仍有 28 株附生物；海葵、船體與附生物本身的頂點數、既有材質及畫質設定不因這項修正增加。查詢只在場景建造時執行，游動時不增加逐根接觸取樣。
- 海葵可見距離小於其高細節支撐岩石的有效距離；沉船所有附生物的可見範圍均小於同一船體的範圍。海扇根部不會隨水流平移離開支撐面。

## 驗證方式

```sh
node tests/parity/habitat-attachment.cjs --local-neighbours
node tests/parity/habitat-attachment.cjs --compiled
```

第一個命令驗證正式建造函式、180 根部、法線、亂數、固定小丑魚 UID、28 株船體附生物及局部鄰近珊瑚。它只重建中央礁體元件，省略不消耗亂數的地面網格；不輸出完整遊戲或已編譯資產。

第二個命令讀取實際 `assets/reef.mesh.gz`，應於完整建置後執行。未重建的 v0.18.36 資產會因海葵根部間隙而失敗，這是原問題的 RED；不能把來源測試通過當成已發布資產通過。

測試的接觸判定使用獨立重心座標三角面求交，不使用製作函式的 BVH 當作唯一判定，也不使用解析海底高度或橢球碰撞代理。CPU 接觸檢查不代替瀏覽器畫面、陰影、自動畫質切換與公開部署確認。
