# 0.18.23 呈現節奏與無日光陰影工作

基線 `dca9fdbeb77628ac83e079b6aca7704e2ad2bccd`（0.18.22）。本輪承接完整商用目標與玩家的畫質／流暢度需求；不縮減原有內容、多人與實體裝置驗收範圍。

## 玩家結果

1. 瀏覽器以 0.1 ms 精度回報正常 60 Hz 時間戳時，不能因微小早到而規律漏畫、再錯降自動畫質。保留既有遊玩／互動觀賞 60 Hz、首頁 30 Hz 工作上限，保留真實 120 Hz 物理、原始間隔、游速、觀察、輸入與暫停時間。
2. 時間容差只補有界的時戳量化誤差，不能掩蓋真實慢幀、合成統計或在高更新率多做完整畫面。早到提交沿既有 deadline 相位推進，不能每次重置到早到時間造成持續漂移。
3. 既有 `oceanSunlessView` 證明整個可見範圍沒有太陽光貢獻時，兩張太陽陰影圖不再清除或繪製。保留場景串流／相交測試、可見幾何、頭燈、AO、粒子、照片與後製；不更改 shader 或太陽裁剪門檻。
4. 深海存檔首次載入即有合法矩陣與完整畫面。深處的幾何／光照／origin／forceShadow 變更不丟失；返回有日光範圍的第一個完成畫面已重建正確靜態及動態陰影。
5. 保留滑鼠／觸控主動選取，桌機／手機自動畫質，個人存檔及既有 43 類生物和完整海域。測試使用真實內容，不靠隱藏生物、縮減解析度或降低幾何達成改善。

## 驗證邊界

沿用已確認的正式 `animate`／RAF → render 與 Renderer → WebGL I/O 邊界：時間與 GL recorder 為明示 adapter，不修改私人函式取得遊戲進度。每一修復先留有效 RED，再做 GREEN；既有與新回歸在最終來源凍結後完成一次全套。

- 排程測試含 60 Hz 的量化／相位差、120 Hz 量化、既有刷新率、真慢幀、首頁／live viewer、背景／pause／stream 等待、強制 resize、游泳／觀察時間、自動降級與回升。統計必須仍是實際提交間隔。
- 陰影測試觀察真正 FBO bind／clear／draw：深水首次、連續／跨格、深處失效後返回原淺水格；保留有效矩陣與正常 GL 狀態。舊測試要求深海無效 shadow 的部分須明示契約變更，不重製 immutable baseline。
- 原生 GPU 同一硬體、同內容／相機／時間／解析度，完整 RGBA 對照；ABBA 計時保留原數據與沒有收益的案例。此輪不改 shader 算式，預期完整像素相同。
- 正常 UI 的桌機／觸控自動畫質入海、游動、深海與返回、主動觀察／照片／重載另驗。時間量化 CPU RED 不能冒充已在實體 60 Hz 裝置重現；觸控模擬不能冒充手機或耗電成績。
- 雙軸獨立 Spec／Standards 審查、打包與指定 Pages 提交、全部公開 manifest 雜湊及公開正常遊玩另列。僅完成相符證據後才描述本輪已交付。

## 界線

本輪沒有實體手機／其他 GPU／電力數據，不推論所有裝置固定 60 FPS，也不保證所有黑閃成因都解決。保留完整多人、公網服務、全內容與商用放行門檻；本輪是具體效能修復，不是整體完成。

時間精度背景：[W3C High Resolution Time 的 coarsen time 定義](https://www.w3.org/TR/hr-time-3/#dfn-coarsen-time)。這是 Working Draft；實作可能使用更粗精度及 jitter，本輪不宣稱涵蓋所有隱私時鐘設定。
