# v0.18.49 海龜划鰭可見範圍

固定基準：`5a0dfe120d6566fa8dd564a2ae4b77322f9a696c`（v0.18.48）。這是完整海龜重製前可獨立修復的現役動作缺陷，不把局部修復當成模型、材質、完整擬真或整體效能目標完成。

## 問題與行為

現役 kind 2 頂點動畫會讓軟肢體在局部 x／y 方向最多位移 .07／.37；`Renderer.updateBatch` 的視錐球卻只有靜止模型 radius。若划動中的鰭仍在畫面內、動物中心已在邊緣外，整隻海龜可能提前被剔除。現有岩石碰撞已保留划鰭位移，不能用碰撞測試代替 renderer 可見性測試。

1. kind 2 的視錐剔除須包含所有相位的動作範圍，採用 `restRadius + hypot(.07, .37)` 的保守球界，再乘最大 instance scale。局部旋轉保長、非均勻縮放受最大 scale 控制；這是三角不等式上界，不是精確最大半徑。每個 batch 計算一次，不在 instance 熱迴圈分配陣列或重算三角函數。
2. 同一規則適用一般畫面與陰影 updateBatch；原 LOD 距離、actor 位置、動畫、材質、模型、接觸路線與其他 render kinds 的剔除行為維持。新增模型若採別的 rig，必須另訂相符動作界，不能直接借用此常數。
3. 正向驗收使用兩個現役 LOD 的全部 indexed vertices、實際 production VS transform feedback 與完整 `2π/1.45` 週期有限取樣（包含起終點）。檢查剛性部位／根固定、有限位置與法線、閉合、獨立微分切線 normal oracle。報告明示取樣間距；解析界補足取樣之間的全部相位。
4. 用實際 GPU posed fin vertex 構造視錐邊界，呼叫真實 renderer 的 batch／updateBatch：仍可見的鰭不得使整隻被剔除；在保守動作界之外必須仍可剔除。覆蓋高低 LOD、旋轉、非均勻尺度、一般與陰影收集。保留基準失敗紀錄。
5. 既有實景 turtle-render 驗證仍核對 compiled／uploaded geometry 與 source，動作觀察改為至少一整個划鰭週期，包含兩端。桌面與觸控模擬沿用原鏡位／光照／自動畫質進入流程；不得為截圖變亮或改動控制介面。
6. 重建、檢查現有靜態剔除與動物接觸、雙軸審查後才發佈。確認 Pages 精確 commit 和公開桌面／觸控正常進入及所有 manifest hashes。不得由本機模擬宣稱實體手機、電池或黑閃問題全面解決。

## 完整模型的獨立狀態

C.J..Goldman 的完整綠蠵龜模型已確認官方 CC BY 4.0 與下載入口；截至本規格建立，瀏覽器官方下載頁要求登入，尚未取得模型本體。研究、原創形狀備選與新版 rig／UV 契約筆記另存，沒有以研究縮圖替代正式素材，也沒有把下載條件當成整個目標停止的理由。
