# 0.18.15 渲染節奏與明確操作

固定基準 `0cc9cc99893abe0063cd717492e41c308964a949`。本輪以 AskMatt 的實作／TDD／兩軸審查流程修正已重現的玩家問題；完整 §1–33 與雙人同遊並未縮減。測試沿用已使用的可見瀏覽器、正式 animate／選取／feature lifecycle 及保存邊界，不新增產品測試後門。

## 玩家結果

1. 預設自動畫質保留。高更新率螢幕不為同樣的遊玩畫面無限制增加全場景工作；潛水及互動觀賞每秒最多約 60 次完整更新／繪製，無操作首頁最多約 30 次。這是提交頻率政策，不承諾所有裝置能達到該 FPS 或特定耗電降幅。
2. 保留現有 120 Hz 固定步長物理與真實時間推進；60／120／144 Hz 的輸入時間軸不改變移動距離、觀察時間、故事計時或動畫速度。保留相機插值及對手把／鍵盤／觸控的正常響應，不以丟棄時間取得省電。
3. 背景、失焦、凍結、選單、照片及串流等待不累積恢復時的大步前進；首次畫面、dirty、尺寸切換與退出暫停可及時呈現。既有延後 resize／保留上張畫面的防黑閃語義必須保留。
4. 自動畫質及診斷不能把刻意的首頁 30 Hz 當成裝置卡頓，也不能把排程略過的 RAF 偽報成渲染幀。真正前景慢幀仍須量測及降級；原有 20 秒量測的固定畫質和解析度約束保留。
5. 手把 B 是明確主動選取目前畫面中央；先前滑鼠 hover 不會改變選到的生物。滑鼠／觸控仍按實際指標位置，沒有自動中央魚名。
6. 玩家從調查冊或調查摘要明確啟用追蹤後，完成一步即更新為該調查的真正下一個測點／棲地；回收後提示返回首頁，回報後結束追蹤。未啟用追蹤不得自動改路標。
7. 玩家自行在地圖、圖鑑或其他功能改標記，立即退出先前調查追蹤；後續調查進度不能覆寫新目的地。兩項故事的追蹤有明確歸屬，切換冊頁不等於改目的地。
8. 追蹤偏好使用原有故事存檔、白名單及有界資料；舊存檔預設不追蹤，不因路標剛好相同就擅自啟用。讀檔／匯入正規化無效追蹤，不授予任務進度、不移動玩家。

## 驗證與交付

先用正式邊界保留有效 RED→GREEN。節奏測試以獨立時間軸驗證完整更新次數、物理時間、觀察時間、狀態切換與慢幀；不可只測新 helper 的相同公式。選取測試需真實選取幾何與正式手把路由；追蹤需可見處理器、正式保存與重載。

原生桌機／觸控使用正常入口、輸入與 RAF 驗證游動、相機、主動觀察、暫停／恢復與調查追蹤；既有黑閃、背景量測及自動畫質回歸保持。高更新率無硬體證據時只聲明 CPU 時間軸／提交工作量，不能稱為實際 144 Hz 螢幕或手機耗電實測。
