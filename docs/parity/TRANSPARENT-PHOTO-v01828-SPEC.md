# 0.18.28 透明組織的攝影散焦

基準 `f38a5ef5a1398bd132cb350701a7be88df440c47`（已發布 0.18.27）。延續完整規格第 13、14、23、32 項，以及 [桶眼魚規格](BARRELEYE-v01825-SPEC.md) 的透明頭罩、遮擋及攝影要求。本輪不取代完整擬真、內容與商用驗收。

## 玩家結果

1. 正常攝影調整光圈與焦距時，桶眼魚透明頭罩與身體有連續、合理的散焦，不出現多個分離輪廓或異常銳利罩緣。正常對焦仍能看見罩內眼管。
2. 保留原個體 UID、0.14 m 尺度、690 m 棲地、解剖、自然動作與高低 LOD；不以放大生物、隱去頭罩、降低透明度或強制小光圈掩蓋問題。
3. 不透明幾何、深度及陰影提交保留。透明頭罩的自身光照、水中衰減、前景遮擋、鏡頭邊緣、兩個展示個體排序與 LOD 過渡都需回歸；不製造前景穿透、黑幀或渲染狀態外洩。
4. 桌機與觸控仍採預設自動畫質；聚焦／未攝影路徑不增加場景工作量，不新增全畫面 pass、貼圖或逐幀生成幾何。散焦工作必須有界、隨透明物體的局部畫面範圍計算，記錄同配置完整 frame 的所有正負計時結果，不用降畫質抵銷成本。
5. 正常選取、觀察、相機控制、真快門、沖印、相簿及重載均需回歸；既有照片與新拍照片保存後，沖印／重載不得改寫同一張照片的 JPEG bytes；水族館也使用同一正式渲染途徑，不能只有測試場景得到修正。

## 驗證

沿用已確認的 Renderer → WebGL、faunaGeometry／faunaMotionPose、正常 UI／保存邊界。先以當前正式 shader、模型及像素建立會抓到重影的 RED；影像判準依連續光學模糊的獨立參考或明確可見症狀，不以特定 draw 次數／實作公式作預期答案。保留原失敗原始資料，修正後使用同一判準並親看實際 PNG。

必要受控案例包括對焦／散焦、前／側／斜上、兩種預設 profile、單採樣與 MSAA、近遠 LOD／連續移動、完全／部分前景、頭燈關閉、兩個個體及畫面邊界。局部修正之外的畫面與未改動的不透明 framebuffer 應保持一致。正常玩家流程與公開產物／入海驗證分列，不互相代替。實體手機、耗電與完整商用門檻保持未完成。
