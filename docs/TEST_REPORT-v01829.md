# 0.18.29 — 透明近拍效能

固定基準 `eaf62daa63ff1adbf79d6342cd8a399eb917d9b1`（已發布 0.18.28），依 [本輪規格](parity/TRANSPARENT-COST-v01829-SPEC.md)。針對上一版已量到的大型透明組織散焦負擔，保留畫質及遮擋後減少 shader 的索引工作。完整內容、公網多人、實體手機、耗電及商用驗收仍未完成。

## 變更

將原本 9×9 迴圈的陣列索引，在初始化時展開成固定 uniform component 的呼叫。保留全部 81 組 bilinear 取樣、y→x 累加順序、微小權重門檻、色彩／alpha 判斷及每個來源深度的前景遮擋。沒有增加 program、貼圖、pass 或幾何；正常對焦、局部 tile、來源影像與 framebuffer 管理均保持原程式。生物、UID、棲地、動作、LOD、自動畫質與保存格式不變。

最終 engine SHA-256：`b07df71c6c837ab0d72ecaf8babdbf6a90d94f74b74d146ec67123b6c256782c`。同 context 配對測試先要求 engine 除該 filter 常數之外的全部來源逐 byte 相同，再從固定舊來源實際編譯並核對 linked shader；只交換 Renderer 的 filter program，保持同一個完整場景和品質。

## 相鄰 frame 的配對 GPU 計時

原生 Chrome、Apple M3 Max／ANGLE Metal，同機桌機 1440×900 DPR 2、觸控 390×844 DPR 3；預設 quality 2／1、scale 1、原 MSAA。每個 shader 先完成至少 60 個暖機 frame，再依 ABBA／BAAB 平衡順序交替取得 200 個完整 frame GPU queries（每個版本 100 筆）。保持場景／相機／光圈／品質固定，完成全部計時後才讀像素或輸出 PNG。觸控另外反轉起始順序重測；沒有丟棄慢樣本、將負差歸零或換算實體手機 FPS／耗電。

## 像素與相容性

完整桌機／觸控各 40 場景、single-sample 各 6 場景及 RGBA8 各 6 場景，六組均通過完整等價 gate，沒有使用 subset。共 104 組場景設定、8 段各 120 幀 LOD sweep、496 個基準與候選 PNG 檔案通過核對。每個場景完整 off/on/on/off RGBA、opaque framebuffer、條件與重複畫面一致；每個 sweep frame 的完整 RGBA 與 shell 訊號也一致。PNG 另讀實際 bytes／SHA-256，沒有靠相似度分數忽略差異。

舊版報告曾有額外 scratch 診斷欄位，無法滿足嚴格 conditions 比對。因此以同一最終 harness 對固定 eaf62da archive 重新取得六組完整基準；未刪除條件或放寬門檻。基準 engine 為 `7a653568e44d0707539483887e58a05fd18c5a092c078c038c03d8de44beea72`，全部候選使用本輪最終 engine。

獨立歷史光學 gate 兩端皆通過：重影輪廓各 0／10，median display-code signal 為桌機 1.010161、觸控 1.016787，focused/off 完整 RGBA 與固定歷史參考一致。這是局部輪廓／訊號驗證，不是整體擬真或物理能量結論。

正常玩家流程桌機／觸控各 31／31：從正式開始、導覽到 690 m 實際個體、明示滑鼠／觸控選擇、觀察、正常 f/2 快門、游至 700 m、沖印與重載均通過。自動畫質仍啟用，預設 quality 2／1、scale 1。逐幀九個 framebuffer 抽樣區未見全黑，GL 0、無 page／console errors，也未出現未選擇就顯示魚名；此抽樣不能證明全部像素、全部硬體或長期不閃黑。

原始證據在 `qa/parity/v01829-filter-cost/`：六個 `*-equivalence.json`、`optical-{desktop,touch}.json`、`natural-{desktop,touch}/report.json` 及所有原始 PNG／快門 JPEG。

## 測量中斷的證據保存

獨立 Standards 審查指出 rapid 配對若中途出錯會只留下最後一筆。已在 browser 保存持續累積的同一筆 record，錯誤收據保留全部已完成樣本、暖機、當前 pending index／mode、當前 block 及原始失敗。明示原生故障測試在第 9 筆後中斷：如預期失敗，保留前九筆 raw GPU samples、兩個至少 60 frame 的暖機及 pending=9；原 program、品質和 GL 狀態成功恢復。這是診斷工具故障測試，不是產品 GPU 失效。
