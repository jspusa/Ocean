## 回歸與修正

先對公開 0.18.31 以正常入口、連續下潛驗證：第一個皇帶魚停靠會在十五秒內自行離開，新的停留驗收因此失敗。收據 `desktop-hold-red.json` 保留原始 failed 狀態；此舊版失敗證實問題，不能算新版通過。

新版 CPU 七個行為案例逐項 RED→GREEN，覆蓋舊資料與非法值、接手保留當次輸入、二十秒持續停留、不重複停靠、生命週期、面板／攝影交接、安全路線失敗及玩家自行到站後的完成。既有三站到達、皺鰓鯊構圖與自由游泳驗證保留；停靠流程改成至少十五秒後明確續行，原皺鰓鯊四秒窗口的 27 個樣本／13 個相位保留，沒有放寬碰撞、尺度或可見性門檻。

第一輪全部 CPU 為 104／105；唯一失敗是 `deepsea.cjs` 仍期待舊 schema。只修正兩個舊保存期望後，該套 15／15 通過，合併 105／105。原始 `cpu/results.json` 與失敗 stdout 不覆寫；`cpu-final.json` 明示合併結果，不稱首次全部通過。打包後靜態 68／68。

首輪原生桌機又找到真實輸入問題：點擊新「繼續前往」後焦點仍在按鈕，既有原生控制項鍵盤保護因此保留 WASD，無法立即手動接手。保留 `desktop-initial.json` 失敗，新增 CPU 焦點斷言先失敗，再將新導覽按鈕動作結束後的焦點交還畫布；沒有放寬全域鍵盤所有權。修正後五套定向 CPU 共 58／58、靜態 68／68；最終 deepsea source SHA-256 為 `c518619d7521b400adb91db3b401185ab5e84f7939dcb1ee548866c390fca175`。修正後完整原生流程另行重跑。
