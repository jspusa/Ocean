# 0.18.53 — retain nearby geometry through transient startup failures

Public v0.18.52 passed exact Pages/tree and 331-file verification. Its desktop live-render smoke passed six swimming/animal frames. The touch profile also rendered but failed the required `streamed` assertion: it had fallen back to the complete scene. A separate repeat boot was healthy with no network/console events. The original transient's specific cause was not captured, so this report does not identify it as the cause of the user's physical-device lag.

The deterministic regression reproduces a matching inefficient path: after one nearby chunk uploads, one other required chunk returns HTTP503. Previously startup disposed the partial stream and fetched `reef.mesh.gz`, although another chunk request could succeed. The fix retries only classified transient startup reads (fetch rejection TypeError, HTTP408/429/5xx), at most three attempts with two-second abortable backoffs. Existing chunk jobs/controllers and resident GPU resources are retained. Runtime request policy remains unchanged.

Timeouts keep their existing twelve-second budget and do not retry. Invalid JSON, manifest/geometry, decompression, decoded size and GPU upload failures still reach fallback promptly. Permanent transient failures exhaust three attempts before the original complete-scene backup. Explicit stream disposal during backoff cancels retries and propagates cancellation rather than starting a full-world fallback. There is no promised whole-boot deadline: the bounds apply to each request and its retries.

## Deterministic evidence

`node tests/parity/scene-startup-retry.cjs` was RED on v0.18.52: index → healthy chunk0 → failed chunk1 → full archive, with partial-resource deletion. The candidate passes 8/8 checks covering retained partial-stream/resource/actor identity, request coalescing and backoff, index recovery, transient classes and preserved messages, exact attempt caps, prompt fatal-data/upload fallback, unchanged timeouts and cancellation without later retries/uploads/full-world requests.

`node tests/parity/scene-startup-deadline.cjs` passes 13/13, including index timeout falling through at twelve seconds to the separate full-scene budget. Independent review found and reproduced a late rejected-fetch boundary: a TypeError arriving after the deadline could be classified for retry before an expired timer ran. The fix checks elapsed time before error classification; the new suspended-timer regression verifies one index request, immediate timeout fallback and no retry timer. Source syntax and whitespace checks pass.

The historical runtime recovery fixture used fixed event-loop drains while native decompression completed independently; the unmodified source also reproduced its scheduling failures. It now awaits actual chunk jobs and the test upload-yield event, with bounded failure diagnostics. All original assertions remain, and one run each against the untouched v0.18.52 source and the candidate passes 11/11. No production deadline or assertion is relaxed to hide the scheduling issue.

The deadline fixture's native late-body checks also await observed array-buffer completion, and held decompression awaits its explicit flush-entry event. Host-only failure deadlines provide diagnostics without advancing fake production time. The final combined run passes startup retry 8/8, deadlines 13/13, runtime recovery 11/11, streaming efficiency 5/5 and static source/geometry/reference/manifest checks.

## Browser and release evidence

The browser regression injects exactly one required-chunk HTTP503 only after another real mesh has become resident. It must retain the same stream and every already-resident GL object, issue exactly two requests for the failed chunk, avoid every full-archive request, and complete real click/tap entry and rendered movement. It records intended HTTP failures separately from unexpected network, console or page errors. This is a software-WebGL desktop/touch-profile test, not physical-phone performance evidence.

`PLAYWRIGHT_PATH=... node tests/parity/scene-startup-retry-browser.cjs http://127.0.0.1:8765/` passes both profiles. Desktop retains 30 resident meshes and touch retains 16, including the same live GL object references. Each failed chunk is requested exactly twice after the bounded backoff; neither profile requests the complete world archive. Both enter through the real click/tap control and complete two actual rendered movement/animal frames with no unexpected page, console or GL errors. The deliberately injected HTTP503 is retained in the receipt. This small-buffer fault test does not measure FPS or certify a physical phone.

No geometry/shader/texture generator is changed in this release. Packaging verifies the existing full-build provenance. All 255 asset files, including the model archive and streamed geometry, remain byte-identical to v0.18.52; its eight exact full-frame comparisons therefore remain applicable to those unchanged render inputs. Independent Standards review has no findings; the Spec review's deadline finding is resolved. Formal-site commit/hash and continuous-swimming checks remain a separate post-merge gate. This incremental release does not establish perfect real-device smoothness or complete Wii feature parity.
