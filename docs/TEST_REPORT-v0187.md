# 0.18.7 游動與顯示恢復

基準 `1449c0f`（0.18.6），依 [本輪規格](SWIMMING-v0187-SPEC.md) 延續 AskMatt 實作與兩軸審查。使用者補充電腦與手機皆有黑色閃屏；本輪修正可重現的共同失敗路徑，不將它宣稱為所有裝置唯一原因。

## 畫面與載入

原 `resize()` 在驗證新 framebuffer 前便清空 canvas、刪除舊目標。配置失敗時例外會中止動畫。現在完整建立候選目標後才替換；任一必要目標失敗，清理候選資源、保留舊目標繼續繪製，相同失敗請求退避 10 秒。MSAA 是可放棄的附加目標。沒有可用舊畫面的啟動失敗仍明確回報。新舊目標會短暫共存，所以這項修正不宣稱降低顯示記憶體峰值。

分區下載的標頭與壓縮內容共用 12 秒期限；失敗後間隔 2 秒，最多三次自動嘗試。玩家可重試目前缺少的海域，或回到上一個完整視野。返回會解除自動移動與抓握；必要時明確切成第一人稱，以留在已載入的視野。長暫停後的舊視野也受到保留。下載與 GPU 上傳切片等待都能被 dispose 取消，不將取消當成載入成功。

等待期間每個分區只有一個錯誤回呼。以四個共用網格、1,000 次更新檢查，沒有再逐幀累積監聽；這是配置量與生命週期證據，不是手機 FPS、電池或溫度量測。

顯示 context 中斷會保存航程並呈現實際保存結果，可下載完整備份，再選省電重新啟動。省電啟動仍開啟自動解析度；不假裝原 WebGL context 已自動復原。匯出進度及失敗訊息顯示在恢復畫面內。

## 操作與存檔

各模組共用鍵盤歸屬判斷，聚焦按鈕、連結、可編輯欄位、IME 與瀏覽器修飾鍵時保留原生行為。畫布上的游動、拍照、工具、觀看模式與選單關閉保留。原生回歸發現地圖關閉後焦點仍在隱藏按鈕，另修復入海、面板及照片關閉後的畫布焦點；首頁維持返回原按鈕，延遲回呼也不得重新奪走焦點。新備份只接受通過正式讀取驗證的主存檔；主檔損壞時不能覆蓋良好備份。備份額度不足仍可嘗試主檔保存，主檔失敗維持警告。

跨分頁過期進度覆寫、日誌的備份與跨照片資料庫的崩潰原子性仍待後續處理。商用完整清單仍未完成。

## 驗證

測試使用原生 Chrome GPU 與桌機、觸控模擬尺寸。GL 配置失敗透過原生 API 邊界故障注入，不冒充真正的實機記憶體耗盡。context 中斷使用 `WEBGL_lose_context`；海域失敗為攔截實際分區 HTTP 回應。照片匯出失敗在 IndexedDB API 邊界注入。

中央 75 份 CPU 套件最終 72 份通過；新增返回案例在修正期間曾失敗，修正後獨立重跑 5/5。三份歷史套件仍為 `deepsea-lifecycle`（舊導覽時限／ROV 契約）、`expedition`（已移除的耗氧規則）、`story-preservation`（已搬遷虎鯨舊座標），與 0.18.6 報告相同範圍，沒有為變綠而恢復舊玩法。

### Standards

獨立審查初次指出下載完成後的 GPU 上傳 RAF 等待無法取消。補上可取消等待與 disposed readiness 拒絕，另由 Spec reviewer 獨立追審關閉。明文程式規範違反 0；最終未解重大程式異味 0。

### Spec

初次指出抓握返回、第三人稱跟隨返回，以及恢復畫面匯出錯誤回饋；追查另涵蓋微觀鏡頭。補足實作與 RED→GREEN 測試後，獨立追審無剩餘重大缺口。此結論僅適用本輪切片。

靜態檢查 58/58 通過。原生 4K／DPR2 連續游動 24 秒，共 1,407 幀；自動比例 1→.935→.97 兩次切換保留的 RGB 最大值為 106／104，下一次繪製尺寸正確、GL=0。這項測試用來驗證真實 RAF 中的切換，不當成各種裝置的 FPS 保證。

發布另驗證 GitHub Pages commit 與全部公開檔案雜湊。幾何、材質、物種和深海棲地保留 0.18.6 版本；179 個區塊解壓內容完全相同，重用既有壓縮檔以保留快取。

實體 iOS／Android、不同顯示卡、20 分鐘熱負載與真人完整操作仍是未完成驗證。本版沒有新的通用 FPS、耗電降低、攝影級畫質或 Wii 全內容對等宣稱。
